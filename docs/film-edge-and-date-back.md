## 1. 上游哪些代码值得看（以及一个硬约束）

**上游是 GPL-3.0。** 抄代码会把整个 App 拖成 GPL，所以只能**抄规格、抄规则、抄测试用例**，实现必须自己写。下面每条都标了"能借什么"。

| 文件 | 能借什么 |
|---|---|
| `desktop/src/shared/filmEdge.ts` | ① 画幅表 `EDGE_FORMATS`：135 = 36×24、半格 = 24×18、645 = 56×41.5、XPan = 65×24…（毫米，片门尺寸）；② 日期规则：**120 画幅不开片边时不印日期**（印在片边上）、全景画幅不印日期；③ `captureDate()` 的解析与校验（年份 > 1800、月份 1–12、按闰年算当月天数），输出格式 `'YY M D`（美式 `M D 'YY`）；④ `shootingText()`：`1/125 F1.6 P +0.3 24mm`，超 22 字符截断；⑤ 每支卷的片边字 `EDGE_WORDS`（`KODAK GB 200-7`、`FUJI RDPIII`…）；⑥ `frameScale` / `dateScale`：日期字号按"片门长边 / 画幅长边"缩放 |
| `engine/src/pipeline/overscan.cpp`（137KB，核心） | **物理模型**：日期与片边字不是贴图，是按**曝光**进负片的 —— 日期走 2700–2800K 的灯（`date_rgb`）、片边字走 4500K（`edge_rgb`），通过胶片的片边感光度积分，再随整条负片一起显影。所以字边会**晕开**。布局全部以**胶片毫米**为单位（s 沿片长、t 横跨）；`Op` 支持 Text / Poly / Circle（圆 = 齿孔/定位孔） |
| `engine/src/pipeline/imprint_raster.{hpp,cpp}` | 字形光栅化：**Liberation Sans Regular/Bold**（OFL）轮廓 → 8bit coverage mask（nonzero winding、8 行子像素、source-over 灰度、高斯软化）。另外内置一套 **5×7 点阵**字体给"数据后背"（645N/F5 那种），"0.5mm 与 1mm 下看起来一样" |
| `engine/cmake/ImprintFonts.cmake` | 字体以**固定 SHA-256** 内嵌（`76d04c18…`），运行期不加载系统字体 —— 这条值得抄：避免"字体缺失就变豆腐块" |
| `engine/tests/host_film_edge.py`、`overscan_checks.py`、`imprint_raster.cpp` | 可以直接照搬的测试思路：mask 覆盖率、几何边界、日期不印的负例 |
| `desktop/src/panels/gate.ts`、`desktop/src/state/session-film-edge.test.ts` | UI 侧状态机：开关 / 画幅 / 日期面（frame vs data）/ 半格拼接时的行为 |

**一句话**：上游把"日期"当**曝光**、把"片边"当**胶片本身**，两者都在负片里；我们做不到（引擎是黑盒、且 pack 尺寸锁死），只能分层近似 —— 下面就是怎么分。

## 2. 我们的硬约束（决定了设计）

1. **引擎是黑盒**：`fotufilm_halide_process_strip` 只吃"场景线性图"，吐"印相输出"，中间插不进曝光 mask；
2. **尺寸锁死**：pack 绑定 4000×3000，任何缩放都会改变扩散/颗粒半径；
3. **画幅是 4:3**：传感器 4:3 横置，落盘转 90° 成 3:4；
4. **旋转在落盘时做**（`PhotoStore.save`），引擎前是横置像素；
5. **不能拖垮拍摄**：任何贴花失败都必须退回"没有贴花的照片"，绝不能让快门失败。

## 3. 功能定义

两个**独立的**开关（默认都关），作用于每一次快门：

### 3.1 片边（Film Edge）

把成品合成到一条 135 胶片上：片基色、两侧齿孔、片边字（按卷）、可选格号。

**画幅**（关键决定）：

| 选项 | 片门 | 比例 | 与我们 4:3 的关系 |
|---|---|---|---|
| **半格 135（默认）** | 24×18 mm | **4:3** | **精确相同**，零裁切、零补边 |
| 135 全画幅 | 36×24 mm | 3:2 | 需裁掉画面高度的 12.5%（上下各 6.25%），且**必须提示** |

> 半格不是一个折中，它是一台真实存在的机器规格：135 胶片上拍 4:3 就是半格。我们的传感器正好 4:3，这是唯一"不撒谎"的画幅。

### 3.2 日期后背（Date Back）

把拍摄日期曝在画面右下角，格式 `'26 11 02`（前导单引号是真实后背的写法）。

- **来源**：`capturedAt`（快门瞬间，D-074 已修）；
- **校验**：照抄上游规则（年 > 1800、月 1–12、按闰年校验日）；
- **两种呈现**（二选一，见 §7 决策）：
  - **盖章**（v1）：落盘时直接画橙色字，边缘锐利、颜色稳定；
  - **显影**（v2）：画进引擎输入 → 走胶片曲线 + 颗粒 + 晕光，字边会软、会被颗粒吃 —— 这才是上游的观感，但要做**反向旋转**（见 §5.2）。

## 4. 数据流与落点

```
快门 → JPEG → decode（4000×3000 横置）
        │
        ├─[v2 显影] 把日期按 -rotation 预旋转画进 source（横置坐标系）
        ↓
     FilmEngine（黑盒）
        ↓
   成品 4000×3000 横置
        ↓
   rotate(rotationDegrees) → 3000×4000 竖置
        │
        ├─[v1 盖章] 画日期（竖置坐标系，右下角）
        ├─[片边] 合成到 135 半格胶片条（竖置：胶片条竖着，齿孔在左右两侧）
        ↓
   JPEG 95 → EXIF → 相册副本 → 缩略图（从合成后的图生成）
```

**为什么片边必须在旋转之后**：胶片条的齿孔方向是"沿片长"的；如果我们先合成再转，齿孔会变成上下两排（错）。旋转后合成，齿孔永远在左右两侧。

**为什么日期默认盖章**：v2 的"画进引擎"要处理旋转、还要接受"字会被胶片曲线压暗/染色"，一旦算错就是**每张照片角上有一块橙色污渍**。v1 盖章是纯后处理，最坏情况是"字不好看"，不会是"照片坏了"。

## 5. 操作逻辑（完整流程）

### 5.1 设置入口

设置页新增一组「成像」：

```
成像
  日期后背        [开关]   关
  日期格式        '26 11 02 ▸   （点开：年-月-日 / 月-日-年）
  片边             [开关]   关
  画幅            半格 135 ▸    （点开：半格 135 / 135 全画幅（会裁切））
```

- 全部落在新的 `ImprintPrefs`（SharedPreferences），**只存开关**，不存每张照片的状态；
- 拍摄页只读显示：取景窗下沿（dock 抓手那一带）出现一行小字 `半格 · 日期`，两个都没开就不显示 —— 用户永远知道"这张会被怎么处理"。

### 5.2 拍摄与落盘（不变量）

1. 开关状态在**快门按下那一刻**快照（复制到 `CaptureRequest`），冲洗中途改设置不影响这一张；
2. 冲洗 + 落盘全程在 `Dispatchers.Default`；贴花也在那里；
3. **失败隔离**：贴花任何一步抛异常（含 OOM）→ 记一条 `Log.w`，用**未贴花**的图继续保存；快门永远成功；
4. **只贴一次**：贴花只发生在 `PhotoStore.save` 内，查看器/详情页只读文件，没有任何"重新导出"路径 → 不可能叠两次；
5. `SavedPhoto.width/height` 用**最终**尺寸（含片边），EXIF 不动；
6. 缩略图从**最终**图生成，照片墙/详情页看到的就是带片边的样子。

### 5.3 详情页 / 相册

- 不新增任何入口：带片边的成片就是一张普通 JPEG（尺寸更大），分享、打开相册、收藏全部照旧；
- EXIF 保持真实（不改拍摄时间，日期是"印上去的"，不是元数据）。

### 5.4 关掉开关之后

新拍的照片不再贴花；**已经贴过的不会变**（它们是烘焙进像素的）—— 与真实胶片一致：拍过的底片不会因为换了后背就变干净。

## 6. 边界与不变量（防 bug 清单）

| 风险 | 处理 |
|---|---|
| 4:3 硬塞 36×24 片门 | 默认半格（24×18，正好 4:3）；选全画幅时**显式裁切**并在设置页写清"会裁掉上下各 6.25%" |
| 日期在旋转后变侧躺 | v2 必须按 `-rotationDegrees` 预旋转绘制；v1 盖章在旋转之后，不存在这个问题 |
| 日期字被胶片曲线吃掉 | v2 走引擎时字会变暗/染色，这是"显影"的代价；v1 不受影响 |
| 贴花 OOM（多一张 3000×4000 + 片边画布） | 合成在独立 try/catch 内；失败退回原图；片边画布用 `Canvas` 直接画到目标 Bitmap，不额外建中间大图 |
| 齿孔画在错误的边 | 先旋转、后合成；齿孔沿"片长"方向排（竖片 → 左右两列） |
| 片边字对不上卷 | 我们的 8 支卷各配一行（`gold200 → KODAK GB 200-7` 等），没有的卷用标签大写兜底；单测遍历所有 stock id 断言有文本 |
| 日期格式/非法日期 | 照抄上游 `captureDate()` 的校验与格式；单测覆盖闰年 2/29、2/30、年份 1800、空值 |
| 格号会倒退 | **v1 不印格号**。要印就得先持久化"曝光序号"（现在只有"存活照片数"，删照片会倒退）—— 那是一个独立决策 |
| 反复开关导致同一张照片尺寸漂移 | 尺寸只由"这一次的开关"决定，且只算一次；不读历史文件的尺寸 |
| 相册副本与私有副本不一致 | 相册副本仍从落盘后的文件**按字节复制**（现有逻辑），贴花在写文件之前完成 |

## 7. 需要你拍板的三件事

1. **画幅**：默认半格 135（4:3，不裁切）—— 要不要同时提供 135 全画幅（会裁 12.5%）？
2. **日期**：v1 先做「盖章」（锐利、安全），还是一步到位做「显影」（走引擎、会晕开，但要处理反向旋转）？
3. **格号**：v1 不印（避免编造/倒退），还是先加一个持久化的曝光序号（多一处存储与迁移）？

我的建议：**半格 + 盖章 + 不印格号**做 v1（一天内可交付、几乎不可能出错），跑通真机后再决定要不要上"显影"和格号。

## 8. 验证方式

- **单测**（纯 JVM）：日期解析/格式化/校验；片边几何（片门毫米→像素、齿孔间距 4.75mm、边距）；stock→片边字映射全覆盖；
- **截图测试**（Robolectric）：带片边的成片、带日期的成片、两者都开、全画幅裁切前后；
- **真机**：开两个开关拍一张 → `adb pull` 看尺寸（应为片边画布尺寸）、方向（字正立）、日期文本（= 快门时刻）、无重复贴花；关掉开关再拍一张 → 尺寸回到 3000×4000。
