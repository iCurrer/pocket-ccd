## 0. 一句话

设计稿是**暗色全屏取景**的专业胶片相机界面，与现行的"红色塑料玩具机身"是两套互斥的视觉语言。复刻在技术上可行，但设计稿里有 **4 类东西不能照抄**：假参数、假胶卷容量、实时滤镜预览、不达标的触摸目标。这四类必须先有结论。

## 2. 设计令牌

### 2.1 颜色

设计稿用 `rgba(255,255,255,α)` 表达层级，落地时统一为带 alpha 的 `Color` 常量，**不引入灰色阶变量**——因为所有这些白都是"叠在深色底上的半透明白"，换成不透明灰会在不同底色上偏色。

| 令牌 | 值 | 用途 |
|---|---|---|
| `AppBg` | `#0B0C0E` | 页面底色 |
| `WindowBg` | `#050506` | 窗口/系统栏底色 |
| `SheetBg` | `#14161A` | 底部面板 |
| `ViewfinderBg` | `#061021` | 取景器兜底（预览未就绪时） |
| `TextPrimary` | `#EDEFF2` | 主文字 |
| `Accent` | `#E7B37A` | 香槟金：激活态、剩余张数、进度条、勾选 |
| `OnAccent` | `#141414` | 金底上的文字 |
| `Ink` | `#FFFFFF` @ 75% | 状态栏文字、取景器 chip |
| `InkStrong` | `#FFFFFF` @ 90% | 变焦激活态底 |
| `InkMuted` | `#FFFFFF` @ 45% | 图标、副标题 |
| `InkFaint` | `#FFFFFF` @ 35% | 缩略图标签、面板描述 |
| `InkGhost` | `#FFFFFF` @ 25% | 参数脚注 |
| `Hairline` | `#FFFFFF` @ 10% | 控件描边、分隔线 |

### 2.2 金属与材质（不能用一个 gradient 糊过去）

| 部件 | 层次 | 参数 |
|---|---|---|
| 取景器外框 | 4 段斜向渐变 | `#4B4F55 → #1B1D20 (36%) → #2D3136 (66%) → #141619`，160° |
| 框内高光 | 1px 内描边 | `#FFFFFF` @ 18%，仅顶部 |
| 框外投影 | 单向投影 | 黑 60%，y+20，模糊 46 |
| 快门环 | 扫描渐变 | `#F4F6F8 → #8D939A(18%) → #E9EDF0(42%) → #767D84(68%) → #E2E6E9(100%)`，起始角 210° |
| 快门面 | 径向渐变 | 圆心 (34%, 28%)：`#FFFFFF → #D9DDE1(58%) → #B7BCC2` |
| 快门红点 | 径向渐变 | 圆心 (35%, 30%)：`#E8705F → #B5382C(70%)`，外扩 4dp 红晕 12% |
| 快门内凹 | 内阴影 | 黑 14%，y-2，模糊 5 |

> **Compose 限制**（2026-10-19 实现后修正）：`Modifier.shadow(elevation, shape, ambientColor, spotColor)` 在 **API 28+ 支持自定义颜色**，minSdk 29 满足，所以框外投影不需要手绘。真正必须 `drawBehind` 的只有两处：顶部 1px 内高光（Compose 无 inset shadow）、快门内凹。原先"三段全手绘"的判断过于保守。

### 2.3 字体

设计稿混排 `Noto Sans SC` + 等宽 mono。Android 上：

| 用途 | 设计稿 | Compose 令牌 | 值 | 说明 |
|---|---|---|---|---|
| 页面标题 | 15px SemiBold | `sheetTitle` | 16sp | |
| 行标题 / 强调信息 | 12px Medium | `optionTitle` | 15sp | 原 13sp |
| 参数值 / 设置项右侧值 / 计数 | — | `value` | 14sp | 2026-10-21 新增 |
| 说明文案 | 12px | `body` | 13sp | 原 12sp |
| 等宽标签 | 10px mono | `mono` | 11sp | 原 10sp |
| 等宽小标签 | 9px mono | `monoSmall` | 11sp | 原 9sp |
| 通用标签 / 单位 | 9px | `label` | 11sp | 原 10sp |
| 胶卷筒仿真印刷 | 8px | `microPrint` | 9sp | **装饰，不承载信息** |

**字号下限 11sp；`microPrint`（9sp）仅限装饰性印刷仿真。**

设计稿自己的主力字号是 9px（占 41 处的 21 处），折到 360dp 屏上只有 8.2dp——
拉丁字母和数字在这个尺寸是"质感"，换成中文就是"纹理"。所以令牌整体比设计稿大一档，
并且**不再允许裸 `fontSize`**：`FilmType` 的 KDoc 写死了下限，`NoBareFontSizeTest`
每次跑单测都会检查 `ui/` 下有没有漏网的 `fontSize = 8.sp`。

文字的**颜色**同样有下限：承载信息的文字最低 `textTertiary`（白 50%，5.3:1），
说明文字用 `textSecondary`（白 60%，7.2:1）。`inkGhost`（白 25%，2.17:1）只允许
出现在图标 tint 与分隔线上。两处例外见下：

- **胶卷库「已装卷」的浅色金属面板**是全页唯一反色区，文字用页面私有的 `Metal.ink*`
  （深色）。白色系令牌落在这块浅底上等于消失。
- **取景器内压在真实画面上的文字**（`AF LOCK`、倍率）不适用合成计算，用 `ink`(75%)
  或更高，不用 `textTertiary`。

**中文字体不引资源**：系统 `FontFamily.SansSerif` 在各家 ROM 上是思源/苹方/小米兰亭，视觉差异在可接受范围。引入 Noto Sans SC 字重文件约 +4MB，等上线前若有包体余量再评估。

## 4. 不能照抄的四类东西

> 这一节是本文件的核心。设计稿是视觉稿，不是数据契约。

### 4.1 假数据必须逐项处置

设计稿里这些数字**全部是硬编码装饰**，与本项目"不伪造"的规则（D-002）直接冲突：

| 设计稿显示 | 现实 | 处置（建议） |
|---|---|---|
| `12`（12MP） | 实际 4096×3072 ≈ 12.6MP | 可由 `programmedSize` 计算真实值 |
| `DNG` | **不产出 DNG**，只有 JPEG | **删除**或改为 `JPEG` |
| `3:2` | 实际 4:3 | **改为 `4:3`** |
| `AF-S` / `AWB` | 未接入对焦/白平衡查询 | 删除，或接 CameraX capability 后显示真实值 |
| `1/125` `f/2.8` `+0.3` `ISO 400` | **CameraX 无此数据** | **删除**（要拿需 Camera2 Interop 读 `CaptureResult`，超出本阶段范围） |
| `24 / 36 EXP` | **没有"卷"容量概念**，可无限拍 | 改为真实累计张数，或接"每卷 36 张"的产品规则 |
| `已拍 12 张` | 应为 `roll.size` | 接真实数据 |
| 进度条 33% | 无分母 | 若采用"每卷 36 张"则真实；否则删除 |
| `FILM OS · 1.4` | 现有 `BuildConfig.VERSION_NAME` | 接真实值 |

**决策需求：** 要么删光这些装饰（界面会显得空，但诚实），要么把"每卷 36 张"变成真实产品规则（有容量、拍完须换卷）。这是产品决策，不是 UI 决策。

### 4.2 实时滤镜预览与 D-036 冲突

设计稿的"色彩风格"面板会实时把 CSS `filter` 应用到取景画面（`sepia/saturate/hue-rotate`）。

但 **D-036 已 ACCEPTED**：取景走原色 CameraX Preview，只有成片才跑 Fotufilm，理由是引擎 12MP 单帧 2.0–3.2s，不可能实时。

三种收法：

1. **预览不加色调**，风格选择只体现在按快门之后的成片（与 D-036 一致，与胶片机逻辑一致）；
2. 预览加一个**廉价的近似色偏**（`ColorMatrix` 一层，不是真引擎），让用户有"选了什么"的即时感，但提示"实际以成片为准"；
3. 推翻 D-036，做实时引擎（需从 3s 降到 16ms，不现实）。

建议 **2**：`ColorMatrix` 一层几乎零成本，且不构成"所见即所得"的欺骗前提是明确标注。但严格说这仍然是"预览与成片不一致"，需要在 UI 上有交代。

### 4.3 图标

设计稿用 `iconify: mdi-*`。落地两条路：

- **引入 `material-icons-extended`**：+2.5MB 左右，图标风格（Material）与线稿风有差异；
- **手画 6 个 VectorDrawable**：flash / flash-off / grid / tune / filmstrip / image-multiple / close / check-circle / chevron-right。

建议**手画**——只有 9 个图标，`ImageVector.Builder` 写出来总共不到 200 行，不加依赖（符合 D-024 的依赖审查要求）。

### 4.4 触摸目标

见 §2.4。必须在实现时统一用 `Modifier.minimumInteractiveComponentSize()` 补齐，并在 T9-012 用 Accessibility Scanner 复验。**视觉可小，热区不能小。**

## 5. 产品结构冲突：首页还要不要

这是比任何像素都重要的分歧。

**规范 §2.2 A 原文：** "首页是产品入口，**不是默认相机取景页面**……进入首页时不应申请相机权限。只有用户主动进入拍摄界面时，才请求必要权限。"

**设计稿：** 打开即取景器，无独立首页。

三个选项：

| 选项 | 做法 | 代价 |
|---|---|---|
| **A 废除首页** | 启动直接进取景器 | 首启即请求相机权限（与规范冲突，需改 §2.2 + 废弃 D-031 的 Stage 手势）；省掉一层导航，最贴合设计意图 |
| **B 保留首页** | 设计稿用于拍摄页，另做暗色首页 | 保留现有导航与"下拉进入"；工作量多一个页面；与设计稿"打开即拍"的第一印象不符 |
| **C 折中** | 首页 = 同一版式但取景器位置放静态品牌/胶卷封面，下拉或点击进入真取景 | 保留权限时机与手势；视觉连续性尚可；实现上要维护两套取景器内容 |

**建议 A**，理由：设计稿本身就是一个完整主界面；T1-007（下拉手势）本来就 `IN_PROGRESS` 且有与系统通知栏冲突的已知风险；胶片相机 App 的惯例（NOMO / Dazz / ProCCD）都是打开即拍。

**但 A 有一个真实代价**：用户第一次打开就弹权限框，且拒绝后必须给一个像样的空态（当前项目没有首启引导）。这必须在 T9 里补一个"无权限空态"任务。

## 6. 实施路径

**并行开发 + 可回退**，不做大爆炸式替换：

1. 新建 `ui/film/` 包，独立实现新 UI，不动 `ui/stage/`、`ui/gallery/`、`ui/result/`、`ui/settings/`；
2. 新建 `ThemeSpec` 抽象层，新 UI 只读语义令牌（见 T9-001），避免重蹈 `RetroRed` 式的材质名命名；
3. `AppRoot` 用 `BuildConfig` 开关或 `debug` 分支切换新旧入口，真机 A/B 对比；
4. 新 UI 通过验收后，一次性删除旧包，同步更新规范与决策。

**为什么不在原地改**：`CameraStageScreen` 720 行的高度耦合了"首页↔拍摄页"插值动画，而新设计根本不需要这个过渡。原地改会留下大量 `progress` 相关的死代码。

## 8. 已知偏差（实现前就承认）

1. **毛玻璃**：`backdrop-filter: blur(6px)` 在 `minSdk 29` 上无对应实现。29/30 用 `#000000` @45% 实色替代；31+ 可用 `Modifier.blur()` 但性能成本需实测，可能统一走实色以保持跨设备一致。
2. **多层阴影**：Compose 无多重 shadow，靠 `drawBehind` 手绘，金属层次会比设计稿略平。
3. **文字渲染**：中文字形与设计稿的 Noto Sans SC 有差异（字重、字面宽度）。
4. **状态栏**：设计稿自绘状态栏，Android 上由系统绘制，位置与字号不可控。
5. **相机画面**：设计稿的夜景/山峦是 CSS 画的假场景，真机是真实预览；构图角标、准星、chip 的对比度在真实画面（可能很亮）上需实测调节，可能要加 `drawBehind` 的局部压暗。
6. **取景器不是成片参考**（D-041）：预览保持相机原色，只叠一层 `ViewfinderVignette()` 暗角。这层暗角是纯 UI 图层，不碰像素；成片暗角来自 FSWP pack 的晕光参数。**两者位置相近但性质不同**，想知道这卷拍出来什么样只能去成片页。后续不许以"预览不够味"为由给预览加 LUT/ColorMatrix。

## 12. 胶卷库返工记录（2026-10-20）

### 12.1 为什么要返工

第一版 `FilmLibraryScreen` 只按 `films.html` 的**文案结构**复刻（哪些字段、什么顺序），
没有复刻它的**视觉承重结构**，上线真机后被判"没按设计、看起来廉价"。两处根因：

| 设计稿 | 第一版实现 | 后果 |
|---|---|---|
| 已装卷卡是 **浅色金属面板**（`linear-gradient(135deg,#F2F4F5,#DCE0E3,#B4BAC0)` + 白描边 + `0 18px 44px` 投影 + 右上白色光斑 + 深色文字） | 深度半透明 `controlFill` + 细描边 | 整页只有一个调子（近黑底 + 灰框），页面上没有光源，必然廉价 |
| 列表每行左侧 **84×108 画格**（占行宽 40%） | 纯文字三行 | 行退化成列表项，没有任何"胶片"意象 |
| 卡片内有 **58×84 胶卷筒插画**（金属筒身 + 顶盖 + 底唇 + 奶油标签） | 无 | 失去唯一的"实体物件" |

结论记这里：**复刻一份设计稿时，先数它的"非文字元素"有几个、各占多大面积。**
只有文字才需要核对字段口径；图形/材质/光影属于版式，不核对就会做出"字段全对但很廉价"的页面。

### 12.2 这一版做了什么

- **金属面板**：`shadow(18.dp)` + `linearGradient(Offset.Zero → Offset.Infinite)` +
  白 50% 描边 + `drawBehind` 径向白色光斑。反色面板配色**不入 `FilmTheme` 令牌**
  （`Metal` object 私有于本页）：它是全页唯一的浅底，做成全局令牌必被误用。
- **胶卷筒**：`Canvas` 三段渐变（筒身横向 0/45%/100%、顶盖与底唇纵向）。
  顶盖照抄原型 `#EDEFF1→#8D9298` 在白面板上**完全消失**，压深到
  `#DBDFE3→#6E747A` 并加 1dp 暗描边才读得出金属边。
- **画格**：有真实成片就显示该卷最新一张（`inSampleSize=4` 解缩略图，`Crop` 填满），
  上下叠 `SprocketRow` 齿孔；没拍过就画胶卷筒。
  **不画原型那套天空/太阳/山脊**——那是"这卷大概长这样"的示意，凭空生成一条
  渐变冒充某支胶卷的成像，撞 D-002。
- **帧点阵**：36 条 `h=6dp` 竖条（已曝光 `#B4703A` / 未曝光 `black 15%`），
  比进度条更能读出"还剩几格"。
- **顶栏**改回原型结构：左右各一个圆钮（返回 / 相册）+ 居中标题与 `FILM STOCK`。

### 12.3 真机暴露的两个实现错误

1. **列表行底部被裁**：右栏写死 `height(108.dp)`，内容实际约 112dp，
   `装卷 / 已装卷` 那行整个看不见。改为 `heightIn(min=108.dp)` +
   `Arrangement.SpaceBetween`——内容短则压到底部，内容长则卡片自己长高。
   **凡是"底部按钮 + 上方可能换行文本"的组合，都不要给容器写死高度。**
2. **计数跨卷串号**（产品层，见 D-046）：切胶卷后计数器仍显示上一支卷的曝光数。
   已改为 `rollShots` 同时按卷起点与当前 `stockId` 过滤。
