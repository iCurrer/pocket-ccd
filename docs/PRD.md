# 1. 产品定义

## 1.1 一句话

**一台装在手机里的玩具数码相机：打开就是取景器，按下快门之后，这一帧才被冲洗成某支胶卷的样子。**

## 1.2 问题陈述

市面上"复古相机"类应用普遍把"复古"实现为一层可实时预览的滤镜（LUT + 颗粒叠加 + 日期水印）。这带来三个具体问题：

1. **预览被污染**。用户在取景时看到的就是成片效果，拍照这个动作退化成"按一下存图"，失去了"不知道冲出来什么样"的期待感。
2. **风格不可解释**。色调来自某个 LUT 文件的作者手感，换个场景就崩；颗粒是靠 Gaussian 噪声叠加，与画幅、像素密度无关，放大后一眼假。
3. **数据不成立**。界面写 `ISO 400`、`D-76 显影`、`¥78`、`36 EXP`，但底层拿不到这些量，也没有真实来源——属于装饰性文案。

Pocket CCD 的解法是把"风格"换成"过程"：

```text
真实胶卷/相纸的实测参数（FSWP pack）
        ↓
物理成像模型（光谱重建 → 显影 → 印相：扩散、晕光、邻界效应、颗粒）
        ↓
成片（取景器全程保持原色）
```

`DEVELOPMENT_SPEC.md` V1.0 最早的定位是"早期 CCD 数码相机风格"。**实现过程中定位已漂移并落定**：当前产品是**胶卷模拟**（8 支彩色/黑白负片与反转片），不是 CCD 风格模拟 `[D-069 及后续]`。本 PRD 采用后者，`DEVELOPMENT_SPEC.md` 的 CCD 部分仅作历史参考。

## 1.3 与"滤镜相机"的差别

| 维度 | 常见滤镜相机 | Pocket CCD |
|---|---|---|
| 预览 | 实时套用成片色调 | 原色预览，只叠一层不碰像素的暗角 `[D-036/D-041]` |
| 风格来源 | LUT 文件 / 手工调色 | 上游 Fotufilm 的胶卷与相纸实测参数，编译成 Halide 内核 |
| 颗粒/晕光 | 全图统一叠加噪声 | 由像素密度推导的物理半径，含邻界效应与光渗 |
| 数据口径 | 界面写死 ISO/工艺/价格 | 只显示能读到的真值；读不到就不显示 |
| 输出 | 预览截图放大 / 降采样 | 全分辨率采集 → 裁切（绝不缩放）→ 全尺寸冲洗 |
| 网络 | 常见账号、云同步、埋点 | 无 `INTERNET` 权限，照片只在本机 |

## 1.4 非目标（明确不做）

| 不做的事 | 理由 |
|---|---|
| 实时滤镜 / 取景器预览效果 | 产品定义的根：预览要是原色，否则就是普通相机 `[D-036]` |
| 视频拍摄、RAW/DNG、专业手动曝光 | CameraX 1.6.2 的 `CameraControl` 只有变焦/曝光补偿/闪光灯/对焦四件事，无 ISO、无快门时间、无光圈、无白平衡 |
| 账号体系、云同步、社交社区、分析 SDK | 无网络权限是隐私承诺的物理保证，不是文案 |
| 虚构胶卷价格、到期日、冲扫进度、订单号 | 没有数据源；排版可借，数据必须能查 `[D-043]` |
| 真实相机品牌 Logo / 型号作为产品名 | 商标风险 `[D-018 方向]` |
| "一卷 36 张"的卷模型 | 整套模型已废止；只保留"这支卷在本机拍过几张" `[D-070]` |
| 用缩放适配不同机型 | 缩放会改变像素密度，等于换光学系统；只允许裁切 `[D-037]` |

# 2. 用户与场景

## 2.1 用户画像

三类用户，**规模判断目前没有数据支撑 `[H]`**，不作为排期依据：

| 画像 | 特征 | 对本产品的诉求 |
|---|---|---|
| A. 胶片/CCD 审美爱好者 | 逛小红书胶片标签，买过一次性相机或二手 CCD | 成片"像真的"，能看出是哪支卷；不要求参数可控 |
| B. 手机摄影玩家 | 会为一张照片挑镜头、挑 App | 要横版相机手感、要能选卷、要能分享原图 |
| C. 开发者/同好 | 关注实现（物理模型、AOT 内核） | 想看工程透明度、想自己替换 pack |

产品的功能取舍以 **A 为主、B 为次**。C 是分发渠道而非用户群。

## 2.2 核心场景（按频次排序）

| # | 场景 | 用户动作 | 成功判据 |
|---|---|---|---|
| S1 | 随手拍一张 | 掏出手机 → 打开 App（直接是取景器）→ 按快门 → 看冲洗 → 看照片 | 3 秒内完成一次拍摄，成片方向正确、贴花正确 |
| S2 | 换一支卷再拍 | 取景页 → 点卷名 → 胶卷库 → 装卷 → 返回拍摄 | 下一张立即使用新卷；重启后仍是这支卷 |
| S3 | 翻看旧照片 | 底部 Tab → 相册 → 点开一张 → 看参数/收藏/分享 | 历史照片有完整参数与动作，返回回到相册 |

| S5 | 关掉贴花 | 设置 → 片边/日期后背 开关 | 只影响新拍的照片，历史照片不变 |

# 3. 产品原则（七条铁律）

这些不是风格偏好，是**已被决策固化、违反即返工**的约束。新需求先过一遍这张表。

1. **打开即取景**。没有首页；`CAMERA` 是根，返回交给系统 `finish`。代价是首次启动即申请相机权限，拒绝时显示空态而不是假首页 `[D-039]`。
2. **预览不碰像素**。取景器只允许一层暗角，不套 `ColorMatrix` 近似色调 `[D-036/D-041]`。
3. **数据要么真读，要么不写**。空白宁可留空，不抄原型编的文案 `[D-043/D-050]`。
4. **尺寸只裁不缩**。采集尺寸 ≥ pack → 中心裁切；< pack → 明确失败并说明差在哪 `[D-037]`。
5. **冲洗之后才旋转**。pack 的空间参数按帧尺寸烘焙，先转再冲会直接失败 `[D-017]`。
6. **写两份就必须对账**。私有目录是权威副本，系统相册是对外副本，两者之间必须有一致性策略 `[D-047]`。
7. **未执行的验证不得标记为通过**。构建成功 ≠ 功能可用；模拟器 ≠ 真机。

# 4. 信息架构

## 4.1 目的地与方向策略

六个目的地，**方向按页面设，不写死在 manifest** `[D-083/D-089]`：

| 目的地 | 页面 | 方向 | 底部 Tab | 性质 |
|---|---|---|---|---|
| `CAMERA` | 拍摄（根） | **横屏** `sensorLandscape` | 显示 | 常驻，相机保活 |
| `GALLERY` | 相册 | 竖屏 | 显示 | Tab |
| `FILMS` | 胶卷库 | 竖屏 | 显示 | Tab |
| `DISCOVER` | 发现 | 竖屏 | 显示 | Tab（脚手架） |
| `SETTINGS` | 设置 | 竖屏 | 显示 | Tab |
| `DETAIL` | 单张详情 | **按入口决定**：从相机进=横屏，从相册进=竖屏 | 隐藏 | 压栈页 |
| （模态） | 全屏查看器 | 跟随宿主 | 隐藏 | 盖住 TabBar `[D-077]` |

三条导航规则：

- **相机是根**：任何页面都能回 `CAMERA`；`CAMERA` 上的返回不拦截，交给系统退出。
- **Tab 是平级**：Tab 之间的返回统一回相机，不回上一个 Tab（否则从设置→相册→返回会回到设置，出不去）。
- **详情是压栈**：`detailOrigin` 记住从哪进来，返回就回哪 `[D-071]`。

> 方向切换的代价已量化：横→竖会重建 Compose 分支。0.8.8 的解法是"**由入口决定方向**"，不再看采集时序——按下快门后详情页保持横屏，看完返回不再重绑相机，同时根除了 `Camera is closed.` 这一类采集被解绑掐断的故障 `[D-089 第四轮]`。

## 4.2 页面清单与职责

| 页面 | 核心内容 | 明确不显示 |
|---|---|---|
| 拍摄 | 取景窗（4:3）、卷名/张数、倍率轨、快门、闪光灯、EV、九宫格、设置、最近一张缩略图 | ISO / 快门时间 / 光圈 / 白平衡 / AUTO-PRO 模式切换 |
| 相册 | 玻璃网格、按卷筛选、收藏筛选、全屏查看器（循环滑动） | 设备上的其它照片 |
| 详情 | 印相、卷名与阶段、真实 EXIF（焦距/曝光/感光度/时间/文件体积）、收藏/分享/在相册打开/重试 | 虚构的冲扫进度百分比 |
| 胶卷库 | 当前卷大卡、候选卷列表、拍不了的卷灰显并给原因 | 价格、到期日、ISO、C-41 分类 |
| 设置 | 片边/日期后背开关、胶卷文件位置、本机数据、开源与素材声明、诊断（仅 debug） | 无实际作用的占位项 |
| 发现 | 本机统计（照片数/收藏/胶卷数/磁盘占用） | 在线内容（无网络） |

# 7. 状态模型与异常处理

## 7.1 拍摄 → 冲洗 → 落盘

```text
Idle
 └─ 按快门 → Capturing（窗口内禁止转屏）
      ├─ 5s 超时 → CaptureTimeout → rebindRequests++ → 提示"已重连相机"
      └─ 帧到手 → Developing（相机已不参与，可安全切版面）
            ├─ pack 尺寸 > 采集尺寸 → 明确失败（说明差在哪）
            └─ 渲染 → Imprinting（贴花，可失败降级）→ Writing（fsync → rename）
                  └─ Publishing（写入系统相册，IS_PENDING 1→0）
                        ├─ 成功 → Done
                        └─ 失败 → delete 回滚 + 记账（该张不参与对账删除）
```

**不变量**：未 `rename` 成功不得标"已保存"；贴花失败不影响成片；发布失败不得删除私有副本。

## 7.2 两份副本对账（四道安全阀）

触发时机：`ON_RESUME` + 进入相册各一次。判活在纯函数 `GalleryReconciler.staleIds`，可单测。

命中任一条件即**保留**：文件名匹配 / `DATE_TAKEN` 秒级匹配 / 未过 2 分钟等待期。

| 阀 | 条件 | 后果 |
|---|---|---|
| ⓪ | 相册补齐（backfill）未跑完 | 整批不对账（补传与对账并发会删光历史） |
| ① | MediaStore 查询失败，或成功但 0 行 | 一张都不删（索引重建/卷重挂载都会返回空） |
| ② | 该张发布到相册失败 | 不删（它从没进相册，"相册里没有"不是删除证据） |
| ③ | 拍摄未满 2 分钟 | 不删（写盘与入库有延迟） |

**已知不对称**：在系统相册"回收站"还原一张照片，照片墙不会自己长回来（只对账删、不对账补）。这是为"宁可不同步也不清空照片库"付的代价 `[D-047]`。

## 7.3 错误呈现原则

- 用户文案说明**发生了什么 + 能做什么**（例：`「GOLD 200」需要 4000×3000，这台设备只能给 3264×2448`），不出现堆栈或错误码。
- 开发侧保留阶段与错误码（`PocketCcdCamera` / `PocketCcdCapture` / `PocketCcdGallery` 三个 tag）。
- 不把完整图像数据写进日志。

# 附录 A 术语

| 术语 | 含义 |
|---|---|
| pack / FSWP | 一卷胶卷 + 一种相纸 + 一次曝光的全部参数，纯小端序列化 |
| pixels-per-mm | pack 空间参数（扩散/晕光/颗粒半径）的烘焙基准；裁切不改它，缩放会改 |
| halo | 分块渲染时每条带上下多算的行数，由 pack 给出，保证带缝不断裂 |
| 片边 | 把成片合成到 135 胶片条上的贴花（齿孔 + 片边字） |
| 日期后背 | 把拍摄日期以点阵字模"盖"在画面右下角 |
| 对账 | 比对私有副本与系统相册，决定哪些私有副本该删 |
